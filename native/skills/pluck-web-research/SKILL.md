# 웹 조사 → 보고서

## 순서

1. **질문 정리**: 무엇을 알아내야 하는지 3~6개의 하위 질문으로 나눈다. 범위가 애매하면 시작하기 전에 한 번만 묻는다.
2. **검색**: `browser.session()`으로 자기 세션의 탭을 연다. 사람이 보고 있는 탭은 건드리지 않는다.
   - 한국 관련 주제는 네이버와 구글을 둘 다 검색한다. 공식 사이트, 정부·기관 자료, 언론 기사를 블로그나 광고 글보다 우선한다.
   - 검색 결과에서 출처를 5~10개 골라 탭으로 연다. 한 번에 너무 많이 열지 말고, 다 읽은 탭은 `close(id)`로 닫는다.
3. **읽기**: `snapshot(id, { textLimit: 8000 })`으로 본문을 읽고 필요한 사실만 메모한다. 메모마다 URL과 날짜(기사 날짜 또는 확인한 날짜)를 붙인다.
4. **교차 확인**: 숫자, 날짜, 가격처럼 중요한 사실은 출처 두 곳 이상에서 확인한다. 출처끼리 다르면 양쪽을 모두 적는다.
5. **보고서 저장**: 작업 폴더에 `YYYY-MM-DD 주제.md`로 저장한다.

## 보고서 형식

```markdown
# 주제
> 조사일: YYYY-MM-DD · 출처 N곳

## 핵심 요약
- 결론 3~5줄

## 상세
### 하위 질문 1
내용 … [1]

## 출처
1. 제목 — URL (날짜)
```

표로 비교해야 하는 내용이면 같은 이름의 `.csv`(UTF-8 BOM, 엑셀에서 한글이 깨지지 않게)도 함께 저장한다.

## 주의

- 로그인이 필요한 유료 기사는 읽은 범위만 쓰고, 읽지 못했다고 밝힌다.
- 확인하지 못한 내용은 "확인 못 함"으로 표시한다. 추측을 사실처럼 쓰지 않는다.
- 채팅 답변에는 핵심 요약과 저장한 파일 경로만 쓴다. 보고서 전문을 채팅에 붙이지 않는다.
