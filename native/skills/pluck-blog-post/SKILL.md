# 블로그 글쓰기·발행

사람이 이미 로그인한 브라우저 프로필을 쓰므로 로그인 절차는 필요 없다. 로그인 화면이 나오면 멈추고 사람에게 로그인을 부탁한다.

## 순서

1. **글감 정리**: 사람이 준 정보(장소, 메뉴, 가격, 느낌)와 사진을 먼저 정리한다. 주소·영업시간·가격처럼 확인할 수 있는 사실은 자기 세션의 탭에서 검색해 확인하고, 확인하지 못한 내용은 지어내지 않는다.
2. **초안을 채팅에 먼저 보여 주기**: 제목, 본문, 태그를 채팅에 보여 주고 고칠 점이 있는지 묻는다. 사람이 "바로 올려"라고 했으면 이 단계는 건너뛴다.
3. **에디터 열기**
   - 네이버: `https://blog.naver.com/GoBlogWrite.naver`. 에디터는 `mainFrame` iframe 안에 있으므로 snapshot의 `@f1:...` 같은 프레임 ref를 쓴다.
   - 티스토리: `https://<블로그주소>.tistory.com/manage/newpost`
   - "작성 중인 글이 있습니다" 팝업이 뜨면 사람에게 이어 쓸지 묻는다. 묻기 어려우면 "취소"를 눌러 새 글로 시작하고, 그렇게 했다고 보고한다.
4. **제목 → 본문 → 태그 순서로 입력**
   - 본문은 문단 단위로 나눠 입력한다. 한 번에 긴 HTML을 `js`로 넣으면 에디터 내부 상태가 어긋나서 저장할 때 내용이 사라지거나 서식이 깨진다.
   - 입력할 때마다 snapshot으로 실제로 들어갔는지 확인한다.
   - 태그는 본문 끝에 `#태그`로 쓰거나, 에디터에 태그 입력란이 있으면 그곳에 넣는다.
5. **임시저장**: 에디터의 "저장" 버튼을 누른다. **페이지를 벗어나기 전에 반드시 저장한다.** pluck은 "사이트에서 나갈까요?" 창을 자동으로 확인 처리하므로, 저장하지 않고 이동하면 쓰던 글이 사라진다.
6. **발행**: "발행" 버튼은 사람이 채팅에서 명확히 허락했을 때만 누른다. 허락받지 않았다면 임시저장한 상태로 멈추고, 화면에서 확인한 뒤 발행해 달라고 안내한다.

## 사진

첨부 사진을 업로드해야 하면 에디터의 사진 버튼은 파일 선택 창을 띄우는데, 에이전트는 이 창을 조작할 수 없다. 사진 자리를 `[사진: 설명]`으로 비워 두고, 사람에게 직접 넣어 달라고 안내한다.

## 끝나고 보고할 것

제목, 저장 상태(임시저장/발행), 글 주소(있으면), 사람이 직접 해야 할 일(사진 넣기, 발행)
